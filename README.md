# FEstyUI

Кидаешь временные файлы в одну папку — программа раскладывает их на изображения, видео и документы. Через 24 часа переносит учтённые файлы в системную корзину. Повторная точная копия фотографии заменяет старую; у новой начинается новый срок.

## Как пользоваться

После установки положите файл в папку, указанную при `festyui init`.
Сортировка обычно занимает 10–12 секунд. Фоновый запуск включается командой `festyui service install`.

```text
FEstyUI/
├── Изображения/
├── Видео/
└── Документы/
```

Клади файлы в саму FEstyUI. Файлы, которые ты положил прямо в подпапку, программа не подхватывает для очистки. Неизвестные расширения остаются на месте. Весь компьютер программа не сканирует.

## Команды

```bash
festyui check                 # работает ли программа прямо сейчас
festyui status                # состояние, учёт и проблемы
festyui logs                  # последние 100 записей
festyui logs --follow         # наблюдать за событиями; Ctrl+C закрывает только просмотр
festyui logs --lines 200
festyui scan --dry-run        # посмотреть план без изменений
festyui service stop          # остановить сортировку и очистку
festyui service start
festyui service restart       # после изменения настроек
festyui service uninstall     # убрать автозапуск; файлы и настройки сохраняются
```

Если текущий терминал ещё не видит команду, используй `~/.local/bin/festyui check` либо открой новый терминал. Код проекта и виртуальное окружение нужны работающей службе: не перемещай и не удаляй папку проекта, пока служба установлена.

`check` сообщает «Работает», «Работает с проблемами», «Остановлена» или «Нет свежего прогресса». Он проверяет процесс, блокировку, свежесть выполнения работы и доступность базы. Он не создаёт проверочные файлы и не обещает, что следующая операция не столкнётся с ошибкой диска.

## Сроки и повторные фотографии

Для изображений, видео и документов сейчас включены 24 часа с первого обнаружения. После выключения компьютера сроки не обнуляются. Просроченные учтённые файлы уйдут в корзину после запуска; новые будут отсчитаны с первого обнаружения.

Повторной считается фотография с полностью одинаковыми байтами, даже если имя другое. Обрезанное или пересохранённое изображение может считаться новым. Разные файлы с одинаковым именем сохраняются с суффиксом `_2`, `_3`.

Старая копия отправляется в корзину только после сохранения новой. Если это не получилось, обе остаются и появляется ошибка. Замену фотографий выполняем отдельно от очистки по возрасту.

Корзину приложение не очищает. Восстанавливай файлы обычным файловым менеджером. Если файл изменён, забран или переименован вручную, программа не удаляет его по старой записи. При сомнении после аварии файл получает статус `review` — нужна проверка. Забери такой файл из управляемой папки и при необходимости положи его заново с новым именем; старые записи не редактируй вручную.

## Настройки

Файл: `~/.config/festyui/config.toml`.

```toml
[documents]
cleanup = true
hours = 24
extensions = ["pdf", "doc", "docx", "txt", "odt", "rtf", "xls", "xlsx", "csv", "ppt", "pptx"]
```

`cleanup = false` отключает очистку категории. `hours` задаёт срок для новых файлов. У существующих сроки сохраняются. После изменения выполни `festyui service restart`. При повторном включении очистки уже просроченные файлы могут уйти в корзину сразу.

База и сведения о работе находятся в `~/.local/share/festyui`. Настройки и база учитывают XDG-переменные Linux. Потеря базы не приводит к очистке всех файлов в подпапках: программа не угадывает старые сроки.

## Ограничения первой версии

- Проверена эта Ubuntu и Python 3.14.4. Для других Linux нужны Python 3.12+, локальная файловая система и, для штатных команд службы и логов, пользовательский systemd. Проверок Fedora/Debian пока не было.
- Нет отдельного окна и значка в панели. `status` и `check` сейчас показывают одну диагностическую сводку.
- Ожидание 10 секунд стабильности не доказывает завершение копирования, если записывающая программа делает длинные паузы. Для больших файлов лучше перемещать готовый файл с того же диска или копировать под временным расширением, затем переименовать.
- Нужна локальная папка без символических ссылок. Перенос использует временную жёсткую ссылку: обе папки должны быть на одном разделе с поддержкой таких ссылок. При ошибке исходник сохраняется, операция требует проверки.
- Защита рассчитана на обычную личную работу, а не на враждебный процесс, одновременно подменяющий пути. Не используй папку для файлов, которые другая программа непрерывно перезаписывает.
- Предпросмотр показывает кандидатов на замену среди уже учтённых фото; окончательное побайтовое сравнение происходит во время обработки. Несколько новых файлов в корне будут сопоставлены при последовательной сортировке.

## Установка на другой компьютер

Скачайте репозиторий:

```bash
git clone https://github.com/nexory-zer/FEstyUI.git
cd FEstyUI
```

Из каталога проекта:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
.venv/bin/pip install --no-deps .
.venv/bin/festyui init --folder "$HOME/FEstyUI"
.venv/bin/festyui service install
.venv/bin/festyui check
```

На Ubuntu пакет `python3-venv` может понадобиться отдельно. Не запускай приложение через sudo. `init` не перезаписывает существующие настройки. Для короткой команды можно добавить `.venv/bin` в PATH или создать ссылку на `.venv/bin/festyui` в `~/.local/bin`.

## Как устроен код

- `config.py` читает настройки и проверяет папки.
- `engine.py` ждёт готовности файла, переносит, сравнивает фото и очищает по сроку.
- `storage.py` хранит записи SQLite и состояние незавершённых операций.
- `daemon.py` запускает цикл, запрещает второй экземпляр и сообщает о прогрессе.
- `preview.py` показывает план без изменений.
- `cli.py` разбирает команды и управляет пользовательской службой.

Например: `run` → цикл `daemon` → `engine.scan()` → перенос → запись SQLite. Периодически `engine.cleanup()` проверяет сроки и вызывает Send2Trash.

Структура компактнее первоначального чертежа ТЗ: связанные операции пока собраны в `engine.py`. Разбивать их дальше имеет смысл, когда это облегчит чтение.

## Разработка и проверка

```bash
.venv/bin/pip install -r requirements-dev.lock
.venv/bin/pip install --no-deps -e .
.venv/bin/pytest -q
.venv/bin/ruff check src tests
.venv/bin/ruff format --check src tests
```

Проверки работают на временных файлах. Интеграционный тест создаёт отдельную временную папку и корзину на разделе проекта, запускает настоящий процесс, проверяет сортировку, очистку, зависание и перезапуск. Локально пройдена 21 проверка на Ubuntu с Python 3.14.4. Другие системы пока не проверялись.
